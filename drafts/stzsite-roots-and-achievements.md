## 12.1 The finding, first

**The project's founding text exists, it is good, and the site does not carry it.** A seventy-slide presentation of 2022 states the rationale in one page, names seven root causes of programming complexity, answers them with seven design goals and thirty-three features, and demonstrates each feature with code that still runs in spirit today. A nineteen-page paper and a 1,109-line narration define the one idea that makes Softanza different from every other library: a function is a linguistic expression, and its name, suffixes, prefixes and parameters form an executable grammar, with no AI, no model, no parser, only code. A family of six pattern languages lifts the regex idea from strings to lists, numbers, time, tables, matrices and graphs. A hundred and thirty-five narrations tell the rest.

On the site today: the phrase "by heart" appears on two pages, "What You Think Is What You Write" on two, the seven design goals on none, the function forms on two (Architecture and Craft, in passing), the six pattern languages on none, the metaphors (Walker, Checker, Yielder, Performer) on eight pages but mostly in the education record, the Ring creator's name on none. The narrations page lists all 134 and renders eight as pages, and the eight are small string and list pieces (`Sit()`, `Diff()`, lists in strings, `InsertSubstrings()`, removing from the left, repetition, the XML parser, emulation), while the mental model, the knowledge dialog, near-natural programming, the function forms and the pattern languages stay links to GitHub. Of 134 narrations, 43 ran on 2026-10-02, 84 did not run and 7 carry no code.

So the work of this dimension is three things: a register of what was achieved so that none of it stays in an unreachable file; a list of where the current design drifted from a founding idea, with a plan to reconsider each; and the pages the site owes to its own roots.

## 12.2 The 2022 presentation, read as the founding text

**The rationale** (slide 2, quoted because it is the manifesto the site lacks): "citizenship in the digital age lacks a critical enabler: programming as a computational thinking asset accessible to all, whatever their knowledge in computer science, their culture, language, age, social or professional profile." Languages and frameworks "are built around machine-oriented metaphors, and not human-centred metaphors"; programmer experience "has shifted from a fun conceptual journey of exploring algorithmic solutions, like it used to be in the 70s, 80s and early 90s, to a daily battle against complexity." Softanza is "an effort towards making programming simple and fun again, humanizing its practice and opening its doors to more people with just one obligation: the ability of thinking logically about the problem in hand, using practical abstractions of the real world, and then expressing the thinking in an executable natural language." The slogan was **Programming by heart!**

**The method** (slide 3): tackle "7 root causes of programming complexity" by design, and build the programmer experience on human-centric metaphors. The two paradigms named in 2022 are **Knowledge Programming** and **Natural-Language Programming**: "a semantic layer that codifies the things of the real world inside Ring objects, organizes them in ontologies to form a domain-specific system of meaning, and makes them usable in writing expressive yet simple algorithms, in almost natural language."

**Five audiences** (slides 4 to 9), each with a recipe: programmers of medium-to-large applications; educators and STEM designers (knowledge units turned into interactive programs, "a ludic game for your learning experience"); linguists and NLP engineers; business analysts and UX designers (specs in natural language, a DSL for the domain, workflows as constraints and rules, a prototype in the same code); data analysts and visualisation designers (acquire, clean, structure with ontologies, show, "interrogate in natural language").

**Seven goals and thirty-three features**, the matrix that structures the deck (slides 10, 11 and the seven goal sections):

| goal | features |
|---|---|
| Expressiveness | fluent design · semantic precision · named params · alternative functions · multilingual functions |
| Flexibility | function suffixes · function prefixes · function free form (FF) · function default form (dft) · params free order |
| Reliability | augmentation of Ring types · functions in 9 domains · on-the-shelf advanced functions · Unicode · ISO locales |
| Consistency | with the Ring type system · over RingQt · over Softanza itself · of the vocabulary |
| Human-centric metaphors | Walker · Checker · Yielder · Performer |
| Practical abstractions | conditional functions (W) · visual orientation (viz) · constraint programming · natural-language programming · knowledge programming |
| Manageability | informative error messages · visualised call stack · measurable performance · cachable functions and objects · loggable functions |

**The nine domains** of 2022 (slide 33): numeric, text, list, date and time, multilingual and multinational, conditional coding (W), constraint programming, natural-language programming, knowledge programming. Today's Atlas has 28 areas; the first nine are all still there under other names.

**What the examples show that the text cannot.** The deck is screenshots of code, and the code is the argument: `Q("Niger").IsOneOf(MyAfricanNations)`, `ContainsBoth`, `ContainsAll`, `ContainsSome`, `ContainsN(2, …)` as semantic precision; `Replace("love", :with = "♥")` as named parameters; `LeadingAndTrailingCharsRemoved()` accepted in either order and shortened to `RepeatedCharsRemoved()` as alternative functions; `الحرف_الأخير()` and `字符数()` as multilingual functions; `NumberOfOccurrenceCS(:Of = "ring", :CS = FALSE)`, `BoxedXT([:AllCorners = :Round, :EachChar = TRUE])`, `vizFindAll("I")` drawing `-^----^-----`, `ReplaceNextOccurrenceFF([])` inferring its own defaults, `dftRange()` and `infRange()` returning the parameters' table; `StzLocaleQ([:Country = :Iran])` and `NamesOfDaysIn(:Japanese)`; a Walker with `:Step`, `:Direction`, `WalkUntil('@item = :Milk')`, a Checker with `:CarryUsing@ = '(@1 OR @2) AND (@3 OR @4)'`, a Yielder with `:CarryUsing@ = '@YieldedValue + @PreviousYieldedValue'`, a Performer with `'@item = upper(@item)'`; `EnforceConstraint('@.IsLowercase')` refusing an uppercase update; `_("Steve Jobs").IsThe(:Owner).Of(:Apple)_` then `? ## 12.3 Functions as linguistic expressions, the achievement that deserves the first page

The paper (19 pages) and the narration (1,109 lines, titled *Writability vs. Readability of Computer Code: Softanza Asks, Why NOT Both?*) make one claim and prove it by code: a function name is a sentence, and the library's naming system is "an embedded domain-specific language" in every function, achieved "without machine learning or NLP systems" through "systematic naming conventions that encode semantic meaning, parameter ordering that reflects natural language structure, flexible form variations, intelligent defaults, self-documenting syntax."

**The forms, as the narration names them today**, with what the live code holds for each (files in `base/` outside tests and archive that define or use the form; counted at 93d7a39):

| form | how it reads | in the code today |
|---|---|---|
| Active | `o1.RemoveAll("x")` acts on the object, "o1, remove all x's, please" | the default of every mutator |
| Passive | `o1.AllRemoved("x")` returns the state, the past participle | the `-ed` family, taught on the site's Learn page |
| Fluent | `Q("…").UppercaseQ().ReplaceQ(…).Spacified()`: the `Q()` suffix, "a chain of actions", a terminator ends it | `Q`, `QQ`, `QR` everywhere |
| Immutable | `QC()` chains over a copy | 9 files |
| Partial | `o1.@All("x").@Removed()`: the `@` prefix moves the chain onto a part, "all x removed" rather than "x all removed" | the `@` small function and `@`-prefixed methods |
| Plural | `RemoveMany`, `FindMany` | 15 files |
| Exceptional | `RemoveNonLettersExcept("_")`, `…ExceptMany` | **0 definitions found**: the paper's own example is not in the tree |
| Negative | `IsNotLetter()`, `IsNotAString()`, `DoesNotContain()` | 11 files; the paper says "not supported in all functions yet" |
| Alternative | `FindNthNext` and `FindNextNth` both valid; `Swap`, `SwapItems`, `SwapChars` by precision | present |
| Named parameters | `SwapItems(:AtPositions = 1, :And = 3)`, "code as narrative" | thousands |
| Conditional | `FindW('{ @item > 5 }')`: W for Where | 7 files define W or WF forms; see 12.6 for the shift |
| Prefixes | `viz`, `rnd`, `dft`, `inf` | viz 9 files, rnd 5, dft 1, inf 1 |
| Suffixes | `CS`, `ST`, `XT`, `Z`/`ZZ` (positions as numbers or as sections), the suffix as "a mutual contract between programmer and system" | everywhere; `NumberOfOccurrenceCS` 13 files |
| Small functions | `Q()`, `@@()` ("a pair of glasses"), `@()`, `QH()`/`QHH()` (history), `L()`, `S()`, `N()`, `v()`, `Vr()`, `Vl()` | `QH`/`History` 7 files, named variables 1 |
| Future | `BeforeQ('').UppercasingFQ("ringo").RemoveFFQ("o")…`: F defers, FF executes, "time-oriented thinking" | `_aFuture`/`AddFuture` 6 files, `SetLastValue` 7; `BeforeQ` itself 0 |
| Random | `rndItems()`, `rndNItems(3)`, `rndRemoveItems()`: "gamification for free" | 5 files |

| Default | `dftRange()`, and `infRange()` returning `[[:Param, :Name, :Type, :Default]…]`, "default values made computable" | 1 file each |
| Free order | `FindNthOccurrence(2, "ring")` or `("ring", 2)` | 10 files define `FindNth*` |
| Misspelled | `WithoutSapces()`, `FindLasteAsSection()`, `NearstTo()` all work: "the intelligence resides in the library itself" | 82 files mention the correction machinery (Levenshtein, did-you-mean) |
| Statement | `AllNumbersInQQX([…]).AreNegativeX()`, `NoNumberInQQX([…]).IsPositiveX()`: a statement and its verification | 5 files, 4 tests |
| To come | Timed, Cached, Versioned forms | named |

**Why this is the first-page achievement.** It is the only part of the project that no other library has as a system. It is older than the planes, it explains the `-ed` suffix the site already teaches, it explains the `Q` the site already shows, and it is what a reader means when they say the code "reads like what I think". It is also the part most exposed to drift, because it lives in thousands of method names rather than in one module. The register in 12.7 and plan B1 answer that.

**Two defects the reading found.** First, the Free form is called FF in the deck, FF in the paper, FF in the code (4 methods) and FX in the current narration, and FF is also the suffix that *executes* a Future chain; one name is doing two jobs. Second, the paper's exceptional-form example, `RemoveNonLettersExcept`, has no definition in the tree, so the exceptional form is documented and not guarded.

## 12.4 The pattern languages: one grammar, six subjects, and what the site may claim

**Regex, redesigned first.** Four deep dives and five narrations record the work: the "softanzified" naming engineering done when the library sat on Qt's regex engine (kept with a historical note after the engine replaced Qt, which is the right way to retire a mechanism); the scope-based design that made regex confusion disappear, and which the design document *Scope-Oriented Programming* (v1.2, 2026-08-16) names as "the founding instance of a Softanza paradigm", later applied to system programming, deployment placement and concurrency, with stylesheets as a fifth candidate; the four pillars, `stzRegex` (semantic wrapper, `Match()` for the whole value against `MatchFirst()` for an occurrence), `stzRegexMaker` (a declarative pattern builder: `CanContainAChar(:Between = ["A", :And = "Z"], :RepeatedExactly = 2Times())`), `stzRegexData` (pre-built patterns, `rx(pat(:email))`), and `stzRegexAnalyzer` (announced, not built); recursive named matching; and `stzRegexuter`, "regex as a computational reactive medium", where a trigger pattern fires a computation (`Trigger(:Price = "\$(\d+\.?\d*)")`, `@C(:When = :Price, :Do = '{ @value = @number(@value) * 1.1 }')`), with four announced siblings (analyser, genetic, linguistic, quantic) that exist only in the narration and in one line of the intelligence architecture.

**The elevation.** The same regex-shaped grammar, braces, `@` tokens, quantifiers, `|`, `&`, `@!` negation, now applies to six kinds of data, each with its class in `base/regex` (10 files, 13,385 lines) and its small function:

| language | subject | one pattern | test files |
|---|---|---|---|
| `stzRegex` · `rx()` | strings | `rx(pat(:email))` | 42 |
| `stzListex` · `Lx()` | lists | `Lx("[@N1-3, @S]")`, stepped ranges `@N{1-10:3}`, uniqueness, nesting `[@N, [@N2], @N]` | 2 |
| `stzNumbrex` · `Nx()` | numbers | `{@Property(Even) & @Property(Prime)}`, `{@Digit(:unique)+}`, `{@Relation(Mod:5=0)}` | 2 |
| `stzTimex` · `Tmx()` | time | `{@Event(Meeting) -> @Duration(30m) -> @Event(Break)}`, `{@Duration(1h..2h:15min)}` over `stzDateTime`, `stzDuration`, `stzTimeLine` | 12 |
| `stzTablex` · `Tx()` | tables | `{cols(3) & unique(id) & @!nulls(email) & avgcol(salary:>40000)}` | 47 |
| `stzMatrex` · `Mx()` | matrices | `{shape(square) & property(symmetric)}` | 47 |
| `stzGraphex` · `Gx()` | graphs | `{@Node(start) -> @Edge(flows) -> @Node(done)}`; its header says quantifiers are "parsed but not yet used by the match" | 25 |

Beside them, the **W conditional DSL** (`'{ @item > 5 and IsEven(@item) }'`), compiled by the engine's expression module, is a seventh small language, and the Atlas's own line for the area already says it: "Regex at full PCRE2 power is the entry point; six pattern languages carry it to lists, numbers…".

**What the site may claim.** The author's phrase is "for the first time in computer science history". The narrations' own comparison tables are the honest measure: Wolfram has list patterns, uniqueness and stepped ranges; Elixir, Haskell and Rust have structural matching; graph query languages exist; complex-event processing exists for time. What no other system has is **one regex-shaped grammar across seven kinds of data in one library, with the same small-function habit (`rx`, `Lx`, `Nx`, `Tmx`, `Tx`, `Mx`, `Gx`), the same `Match`/`Explain`/`Debug` surface, and the same tests discipline**. That sentence is defensible on the site; the superlative is not, and the site's own law (every claim links to its proof) would refuse it.

## 12.24 Ruled by the author 2026-10-07 23:09 UTC: the shell kit carries both shells, the page in the browser and the window on the desktop; the foundation already has the law for it, one declaration, two projections, proved to agree, and a guard that does exactly that for pictures

**What the record already says about carrying two.** The foundation does not need a new principle for this; it has one and has used it twice at the layer below.

- The GUI plane's authored surface, `stzUiDocument`: "the file is the CONTRACT, and RML (native) or HTML (web) are its projections", one `.panel` text, two renderings, and the plan's §3 states the same one level up, "the CSS/RCSS profile is a contract, RmlUi is one conforming implementation and a browser is another, and conformance fixtures prove they agree".
- The graphics plane's doctrine since GR2b: "a picture is described once and rendered twice, so the two backends cannot disagree about where anything sits", and the guard `gui_tier_agreement_narrated` (24 assertions) exists because, in its own words, "until this file, nothing had ever checked it. - The window exists on the native side, `stzWindow` in the graphics plane, and the laid-out interface, `stzPanel`, draws through the one display list; the page exists on the browser side, embedded in a binary by the sound studio and served from the language by `stzAppServer`.

So "both" is not two shells. It is one chrome declared once (B43) and two shells that project it, and the law that comes with it is the one GR2b already paid for: the two must be proved to agree, by a guard, and not argued to.

**What each shell is for, in the record's own words.** The browser shell: "one file to run… no port to pick, no page to point it at, no server to start separately" (the sound studio); zero install on any machine with a browser; the same page an agent, a remote reviewer or a phone can open; and its named costs, "the UI is a browser tab rather than a native window, so it inherits the browser's file-access model and its window chrome; a locally-bound HTTP port is a surface that must be treated as one" (RingPad's charter). The native shell: "a single executable binary. No runtime. No framework… ZinCode on a 2015 laptop must feel faster than VS Code on a 2023 MacBook Pro"; "input-to-screen under 16 ms on any modern hardware, no exceptions" (the ergonomics specification); no port, the host's file dialogs and window, the GPU through the graphics plane for the large code graph that RingPad names as the one place the engine "earns it". A solution's author picks the shell per deployment, or ships both from one build, as the sound studio ships one.

**The three constraints that carrying both adds.**

1. *One declaration.* No chrome element exists in one shell and not the other; a region, a cell or a verb is declared in the `.panel` or it is in neither. A shell-specific affordance (the browser's tab, the window's title bar) is the shell's and is not declared.
2. *Agreement proved.* The tier-agreement guard is extended from pictures to the chrome: the empty shell and three populated states rendered in both projections, boxes compared within the tolerance the existing guard already uses, and every Zui verb traced in both. A disagreement fails the build of both.
3. *The latency measured, not inherited.* ZinCode's 16 ms is a constraint on both shells, and RingPad's charter says of the browser shape that it "has been measured for a sound studio and not for an IDE". The two trade-off lists are printed as the record wrote them, each under its shell, so a reader chooses with the costs in view.
