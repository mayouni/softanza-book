## 2. The concept as the field holds it

Three practices, each held today as a tool beside the program, with its own configuration:

1. **Plan, then apply (infrastructure as code and deployment pipelines).** The record names its own references: "CI job DAGs with
   `needs`, Terraform's resource graph, apply-or-revert" and "Kubernetes `resources.requests` + the scheduler"
   (`base/doc/design/SOFTANZA_DEPLOYMENT_PLAN.md` §1, first committed 2026-07-22), and maps eight such ideas to its own verbs in §5. The
   field's habit: the plan is a file for a tool; whether the wrong actor may apply it is a policy. The record states the loss it answers:
   "it's a convention, enforced by hope" (`SOFTANZA_DEPLOYMENT.md` §1, 2026-07-22). (Terraform's plan/apply and Kubernetes' scheduler:
   *general knowledge*; no date read from the record.)
2. **Service virtualization and the test double.** A vendor's test mode with published test cards, an HTTP stub server of the WireMock
   kind, and record-and-replay libraries of the VCR and nock kind. The record's plan names the last two as the idea it generalises
   ("the VCR/nock idea, Softanza-native", `SOFTANZA_SERVICE_VIRTUALIZATION_PLAN.md` §3b, written 2026-07-23). The field's habit: the
   double lives in the test suite; production is a different file. The record's complaint: "No gateway will decline a card because you
   asked nicely" (`stz-service-virtualization-code-first-subscribe-later.md`, 2026-07-25). (WireMock, VCR, nock, vendor test modes:
   *general knowledge*; dates not read.)
3. **Emulators and simulators.** A phone emulator, a board emulator, a local stand-in for a cloud. The record's own sentence on the
   genre: "simulators *lie*. They mock the database, stub the device, approximate the compute" (`SOFTANZA_EMULATION.md` §1, 2026-07-22).
   The record also uses a board emulator for the declared machine (the machine boots in QEMU, study 12.13 table, row "the machine"; that
   repository is not this chapter's). (Android Emulator, iOS Simulator, QEMU: *general knowledge*.)

What the three share: each is a separate tool with its own configuration, and the program itself knows nothing of it. The same shape as
chapter 28's closing line of its section 1, which I do not repeat. A fourth, smaller practice sits under the registry: configuration
by environment and dependency injection (the Twelve-Factor App, 2011; *general knowledge*), which the plan cites by pattern, not by
name: "a duck-typed seam ... swapped for a real vault client at deploy" (`SOFTANZA_SERVICE_VIRTUALIZATION_PLAN.md` §2, row `stzVaultResolver`).

## 5. The decision, and what was refused

All of it from the library's design documents and narrations (written in sessions; no author line; dates are the first commit that
added the file in the live checkout, read for dates only). The author's own words on this chapter's subject: the structure line, and
the question in the service plan's header, which I quote at section 13. Where I write "refused" I mean the document says the design
declines it.

1. **Refused the simulator that lies.** "Teams paper over this with simulators — but simulators lie." And: "Softanza's answer is that the
   emulator does not mock." Each part runs "the same compiled engine artifact that will ship to its target". (`SOFTANZA_EMULATION.md` §1, §2; 2026-07-22.)
   Caution: the proof that the engine runs in a browser is not in the pinned tree (section 8).
2. **Refused to re-ship what the target does well.** The rule: "The edge carries a capability only if it is critical and (Softanza-unique or
   weak/absent on the target platform)." Regex is a construct over the platform's own, "never PCRE2 compiled to wasm"
   (`SOFTANZA_EMULATION.md` §4). Run: block 5 shows `Unicode [target]`, `Neural [server]`.
3. **Refused tool sprawl and the convention enforced by hope.** "the target should be one config away, and deploying to it should be one governed act"
   (`SOFTANZA_DEPLOYMENT.md` §1); "who may deploy" is otherwise "a convention, enforced by hope". Run: blocks 7, 9, 11.
4. **Refused an inline secret.** "Secrets never inline. A site carries an auth reference, not a key." (`SOFTANZA_DEPLOYMENT.md` §2.) Run: block 11.
5. **Refused to touch reality by default.** Production commits "only if the actor may commit"; "So it is safe by default: a bare Deploy(:Production)
   with no actor set touches nothing." (`SOFTANZA_DEPLOYMENT.md` §5.) Run: block 7 and the no-actor run.
6. **Refused the agreeable fake.** "an agreeable fake is more dangerous than no fake at all"; "Silence is the worst answer"; the lenient mode answers 501 because "A miss must never be mistakable for success"
   (`stz-service-virtualization-code-first-subscribe-later.md`, 2026-07-25). Run: block 14.
7. **Refused "fake versus real" as the whole truth.** "fake-vs-real was too coarse": four postures now (sandbox, local, live, conformance), the third added when the database exemplar
   showed sqlite is "a real database in a file you own" (`SOFTANZA_SERVICE_VIRTUALIZATION_PLAN.md` header, phase 2; code header of `stzServiceRegistry.ring`). Run: block 15.
8. **Refused a gate that fails open.** The registry once kept its state in attributes, so attaching it to a delivery took a snapshot and "the gate would have passed
   an unsound surface". The narration: "a gate that fails open is worse than no gate". The fix: state in a table keyed by id, "every copy IS the registry"
   (plan header, phase 7; narration "A gate that fails open"). The gate is read by `service_delivery_narrated` scene "the registry is ONE registry".
9. **Refused to virtualize model quality.** "frontier-model QUALITY cannot be virtualized" is stated before the features (plan, phase 5). What the sandbox sells instead:
   determinism, a cost you can assert, offline. Run: block 14.
10. **Refused to ship the live adapters.** "The live Stripe/PayPal/Adyen adapter is deliberately not shipped (account + key + network = infra-gated)"; the contract is
    defined and the registry refuses to let the fake ship in its place (plan, phase 4). The narration: "deliberate rather than unfinished".
11. **Refused to ask a question in the wrong frame.** `MayGoLive` "used to ask about soundness in the current phase", so with a fake bound it "answered yes"; now it is asked in the
    production frame whatever the phase (narration, "The agent that can touch nothing"; code comment on `MayGoLive`). Run: block 16.
12. **Refused to say the restaurant's need was the design's origin.** The site: the emulation and deployment designs "take a solution named" with the restaurant's product name "as their
    example ... It is an example there, not the origin of the design." (`D:\GitHub\stzsite\content\en\forged.md`, line 34.) The guards and narrations carry that name as the sample
    solution's: the book must rename it (Hazards). This is the same refusal as chapter 28's last paragraph of section 4; do not repeat the story, point.
