## 2. The concept as the field holds it

What programmers mean today by "many agents on one codebase" is, in the main, one of three things.

1. **A multi-agent framework**: a supervisor or a graph of agents inside one program, passing messages through a broker. Microsoft's AutoGen (2023), CrewAI (2023-2024) and LangChain's LangGraph (2024) are the named examples. *General knowledge; the record holds no field study of them.* The record defines itself against this shape: Bangalo "is not a multi-agent framework and must not be described as one. No scheduler, no supervisor, no broker, no agent graph" (`D:\GitHub\bangalo\CHARTER.md`, "Boundaries"). DOCTRINE says the same: "the substrate is git and a directory" (`DOCTRINE.md`, "What this is not").
2. **An instruction file the agent loads**: `CLAUDE.md` for Claude Code (Anthropic, 2025) and the `AGENTS.md` convention (2025). *General knowledge.* The record knows the second as a door it still owes: compass found "no AGENTS.md, no llms.txt" at stzlib (`memos\2026-10-02.md` line 62; `memos\2026-09-25.md` line 693). The estate's own form of this is the coordination block that Central installs into eighteen sibling `CLAUDE.md` files (`protocol\CLAUDE-BLOCK.md`, named in `CLAUDE.md` and `protocol\PX.md` §4).
3. **The ordinary team practices of git**: branches, pre-commit hooks (git's `githooks`), code owners (GitHub `CODEOWNERS`), architecture decision records (Michael Nygard, "Documenting Architecture Decisions", 2011). *General knowledge.* The estate uses hooks (three PreToolUse hooks, `bangalo\hooks\README.md`) and an append-only rulings ledger (`stz-principal\decisions\LEDGER.md`); the record does not cite CODEOWNERS or ADRs as models.

The field's frame: the agents are the system, and coordination is a runtime feature of the agent program. The record's frame: the files are the system, the sessions come and go, and each rule exists because a dated failure paid for it.
