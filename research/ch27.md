## 2. The concept as the field holds it

**Layered libraries.** Inside one codebase a platform is drawn as a stack with one rule: an inner layer knows nothing of an
outer one. The cleanest peer is Rust's `core`, `alloc` and `std`: three depths of one language, chosen by the target. The record
itself names it: "The closest peer is Rust's `core`, `alloc` and `std`" (`drafts\stzsite-roots-and-achievements.md`, 12.15; the
study's words, 2026-10-07). Rust enforces it by its compiler; Softanza holds it by entry files (§8).

**An engine behind a C interface, bound by every host.** The field's habit is a native library with a plain C ABI, wrapped
thinly by each language: SQLite is the common example (general knowledge, well established: one C library, bindings in nearly
every language). The record states the same design for the engine: "Language clients are thin FFI bridges that add syntax and
paradigms -- never computation" (`SNAP\base\doc\design\SOFTANZA_ENGINE_ARCHITECTURE.md`, §1). Modern native engines written in Zig
and meant to be embedded exist (general knowledge, I cite none: the chapter should name none unless the author does).

**A new runtime under an old surface.** The field has done this repeatedly: a language keeps its surface and its libraries and
changes the machine beneath. The record's own example is a typed descendant of Lua: `D:\GitHub\ringpp\NOTES.md` line 52, "Luau
(Roblox's typed, gradually-checked Lua descendant) ... interpreter-only, no JIT" (the estate measured against it; the file is
undated in that section, the benchmark section is dated 2026-08-29). Another is PyPy beside CPython (general knowledge, 2007
onward). Both teach the same thing the record teaches: the surface is the promise, the runtime is the part you must measure.
