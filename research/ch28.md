## 2. The concept as the field holds it

The chapter is a project told as a maker's story, so the "concept" is four practices the project had to answer. The field
holds each as a tool or a ceremony apart; the record holds them as one declared world.

1. **A fixed scope for a cycle.** In Scrum, the scope of a sprint may be clarified as more is learned but the sprint goal
   does not change (the Scrum Guide, 2020; *general knowledge*). In Shape Up, time is fixed and scope is variable, and ideas
   are kept out of the running cycle (Basecamp, 2019; *general knowledge*). The restaurant's version is stricter and written
   down: « aucune idée nouvelle n'entre en cours de cycle ; toute entrée exige une sortie écrite » (no new idea enters during
   a cycle; every entry needs a written exit), `restolean/livrable/RestoLean-Cadrage-V2-Amor.md:187`. The field keeps this in
   a process; the project kept it in a file, a notebook (5.3).
2. **Trying a service before paying for it.** A payment provider's test mode with published test cards, and HTTP stubs of
   the WireMock kind (*general knowledge*). The record's own field note is the plan's caveat: "A double is not the real
   service" (`base/doc/design/SOFTANZA_SERVICE_VIRTUALIZATION_PLAN.md` §8), and the narration's sentence: "an agreeable fake
   is more dangerous than no fake at all"
   (`base/doc/narrations/stz-service-virtualization-code-first-subscribe-later.md`).
3. **A performance budget.** Web performance budgets in CI (Lighthouse CI; *general knowledge*) and Core Web Vitals, judged
   at the 75th percentile of real page loads (Google, web.dev, 2020; *general knowledge*). The record has it first-hand: the
   owner's measurement protocol reads « Vitesse mesurée au p75, Android milieu de gamme, 4G réelle (Core Web Vitals) »
   (`restolean/livrable/virage/RestoLean-Addendum-Amor.md:73`, 28 July 2026). The library's own field study, written against
   the field "as of early 2026", names Micrometer, OpenTelemetry and Prometheus
   (`base/doc/design/SOFTANZA_PERF_VS_THE_FIELD.md`, header and footer, dated 2026-07-29).
4. **The super-app.** The field's picture: a host that embeds a runtime and runs mini-apps (the design names two, FinClip and
   WeChat; `base/doc/design/STZSUPERAPP_DESIGN.md` §1). The record refuses the host: "worlds, not mini-apps; a governed graph,
   not a host container" (same file, §1). Chapter 4 told this; here it is a client's order of work drawn as worlds.

What the four share: the field keeps each outside the program, as a service, a tool or a ceremony. The record asks whether
the program itself can know it, that is, declare it and be judged by it.

### Block 1 · the Lock, as the nearest the library gives (a rule over a cycle's worlds) · KEPT, with a caveat

written admission is a finding. **Caveat for the writer:** no file of the library carries the Lock as a rule (see 5.3 and
8). The project kept it in documents (the notebook, the pact). This block is built from the library's graph rules
(`base/test/graph/graphrule_object_narrated.ring:139-170` proves the `missing` operator) and must be introduced as "the
nearest the library gives", never as the restaurant's own code. 17 lines; the writer may cut after the report.

```haro
oRule = new stzGraphRule("the-lock")
oRule.SetDomainQ("scope")
oRule.WhenQ("kind", "equals", "world")
oRule.WhenQ("admitted-by", "missing", "")
oRule.ThenViolationQ("a world entered the cycle with no written admission")
g = new stzGraph("cycle-1")
g.AddNode("customer-phone")
g.SetNodeProperty("customer-phone", "kind", "world")
g.SetNodeProperty("customer-phone", "admitted-by", "the opening scope")
```

### Block 3 · service virtualization (1): a sandbox that refuses what a real gateway refuses · KEPT

### Block 6 · the speed budget as a promise, judged by the performance plane · KEPT
