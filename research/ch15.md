## 2. The concept as the field holds it

**Paragraph one (strings, and what the word "pattern" means to a programmer).** For a working programmer a pattern is a regular
expression: a compact notation for the shape of a string, handed to an engine that says whether the text fits, and where. The
engines are old and well known; the one this library sits on is PCRE2, which the library's own engine header names
(`engine/src/regex.zig` line 3: "PCRE2 backend replacing the custom recursive backtracker."; `engine/build.zig` line 301 pins
`pcre2-10.47`). The site's area page, rendered 2026-10-01 at commit 0e72e2e2c, measures it against PCRE2, RE2 and Oniguruma
(`D:\GitHub\stzsite\en\atlas\regex.html`). For data that is not text the field uses other tools, one per medium and none
shared: structural pattern matching in the languages of the ML family, Rust and, since Python 3.10 (October 2021, PEP 634),
Python; schema checks for lists and records; data-quality libraries for tables; `MATCH_RECOGNIZE` (row pattern recognition, SQL:2016)
and stream engines for sequences over time; graph query languages whose core is a path pattern such as `(a)-[:KNOWS]->(b)`.
(General knowledge, well established. The record holds no dated study of any of these and the chapter should not invent one.)

**Paragraph two (why a closed notation wins).** The estate's own field study, written 2026-08-06, lists the small languages
that survived and names regular expressions among them, with one profile for all: "closed grammar · one domain question ·
plain text · tiny surface · spec plus conformance · decades-stable" (`D:\GitHub\ringua\docs\landscape.md` §2, line 52). A
pattern language is exactly that: one question, "does this data fit?", in a few characters. What the field does not offer is the
same notation across media. The narrations make comparisons with the field in tables (Listex against Wolfram, C#, Rust, Haskell,
Python; Numbrex against Python, JavaScript, Java, Ruby; Timex likewise), but the same sort of grid in the Reaxis article is
"undated and uncited" in the record (`research\ch09.md` line 621, after study 12.22), and I found no date or source in these either.
**The chapter should print none of those grids.** The study's own measured sentence is the safe claim: "one regex-shaped grammar
across seven kinds of data in one library, with the same small-function habit" (study 12.4, "What the site may claim"), and its
refusal of the superlative, which the author's phrase "for the first time in computer science history" would be.

## 3. The first principle

The sentence the record returns to, in the library's own narrations, is the same in every medium:

> "Instead of instructing the machine *how* to test a condition, you simply state *what* you mean."
> (`base/doc/narrations/stznumbrex-pattern-language-for-number.md`, section "Numbers as Patterns, Not Procedures")

Its echoes: Timex, "`stzTimex` lets you *declare* how time should behave — not compute it"
(`stzTimex-A-Pattern-Language-for-Time-in-Softanza.md`, Conclusion); the declarative builder, "focus on what you want to match
rather than how to express it in regex syntax" (`stzregexmaker-making-regex-human-freindly-narration.md`, Conclusion); the site's
area page, "so you state what you mean, not how to test it" (`stzsite\en\atlas\regex.html`). The shape of the family is in the
engine design: "The backtracking engine, constraint solver, and pattern compiler are the same across all domains -- only the
token vocabulary changes." (`base/doc/design/SOFTANZA_ENGINE_DESIGN.md`, section "Domain-Specific Pattern Matching", status
PLANNED). **Mark for the writer: that second sentence describes a design. At main the vocabulary changes and so does the code.**

Suggested one-line statement for the chapter (mine, from the above; the author's wording is wanted): **a pattern is a rule
about the shape of data, written as data, and the same habit serves seven kinds of data.**

## 5. The decision, and what was refused

The record holds **no ruling by the author specific to the pattern family** (study 12.4 is a reading, not a ruling; it carries no
"ruled by the author" line). What the record holds are the author's own articles (the narrations), design documents and a
session's study. Distinguish them in the chapter.

**Decided, in the author's articles (the narrations are his):**
- To make a pattern a statement of meaning, not of procedure: "you simply state *what* you mean" (`stznumbrex-pattern-language-for-number.md`).
- To carry the regex idea to non-text data with one grammar habit: braces, `@` tokens, `&`, `|`, `@!`, `@cs:`; lists keep square
  brackets (`[@N, @S]`), the other five use braces (`{...}`). **Note: not one grammar.** The brackets differ.
- To keep the old notation intact for text and put clearer names around it: the site's area page, from the library's documents,
  "Simple matches are not reinvented: a classic pattern string, named groups and captures work as written"
  (`stzsite\en\atlas\regex.html`, "Kept from the best practice"). The Qt-era naming work is kept "for educational value"
  (`base/doc/deepdives/qt-softanzified-reengeneering-regex-naming-deepdive.md`, historical note), the right way to retire a mechanism (study 12.4).

**Decided, in a design document (the library's, read as the plan):**
- One pattern engine for every domain, only the vocabulary changing: "The backtracking engine, constraint solver, and pattern
  compiler are the same across all domains -- only the token vocabulary changes." (`SOFTANZA_ENGINE_DESIGN.md`, status PLANNED;
  `SOFTANZA_ENGINE_ARCHITECTURE.md` line 760: `pattern | stz_pattern | PLANNED`).
- Compose, do not rebuild: "compose, do NOT build a new engine -- Graphex proves the layering"
  (`SOFTANZA_INTELLIGENCE_ARCHITECTURE.md`, section 5.2, about the future part-of-speech chunker built on Listex).

## 9. Six doors

- **The programmer.** One habit across seven kinds of data: a small constructor (`rx`, `Lx`, `Nx`, `Tbx`, `Mx`, `Tmx`), a pattern in
  a string, `Match`; and the pattern is data you can read (`Tokens`, `Explain`) and compose (`And_`, `Or_`, `Not_`). Use the six
  verified ones; build nothing on the cache of a reused list pattern.
- **The analyst.** A data-quality rule is a sentence of the table language: `{cols(4) & unique(id) & @!nulls(email) &
  avgcol(salary:>40000)}` (the narration's own example; I ran its parts, block 7 and the verified `unique`, `nulls`, `completeness`
  terms in an employees table). The person who owns the data can read it.
- **The designer.** A pattern states a shape the interface can show before the data arrives, and a half-typed value is answered
  "on the way" (block 2). The word in the area page is "as you type".
- **The decision-maker.** A rule is a line, not a procedure: it can be reviewed and its verdict is a number, 1 or 0. The limit to
  say beside it: a pattern with an unknown word is not refused (E2), and a graph arrow is "later", not "next" (E3).
- **The educator.** The course teaches patterns in two chapters (8, text; 9, structure) in English, French, Arabic and Hausa, and
  its exercise is checked by running the learner's program (`ex-09-01`, tutor's rule). The ladder is a curriculum: text, list,
  number, table.
- **The agent.** A pattern is a small closed notation an agent can be held to and can read back (`Tokens`, `Explain`). Today the
  agent must be told that three of the media cannot yet refuse a word they do not know, and that induction (writing a pattern from
  examples) is reserved, not built (chapters 17 and 18).
