## 2. The concept as the field holds it

**The platform picture.** The field draws a platform as a stack of boxes: hardware or kernel at the bottom,
runtime and libraries in the middle, applications on top, often with a "cross-cutting" column for security
or tooling. The Android "platform architecture" diagram (Linux kernel, hardware abstraction layer, native
libraries and runtime, Java API framework, system apps) is the familiar instance (general knowledge,
developer.android.com, "Platform architecture"). Inside a codebase the same picture becomes a dependency
rule: "source code dependencies can only point inwards" (general knowledge: Robert C. Martin, "The Clean
Architecture", 2012 blog post; *Clean Architecture*, 2017). The closest technical peer the record itself
names for Softanza's layers is Rust's `core`, `alloc` and `std`, "three crates for three depths of host,
chosen by the target and not by a flag" (study 12.15).

**The super-app picture.** For applications, the field's picture is a host: "The industry's 'super-app' is
a *host* that embeds a *runtime* to run sandboxed *mini-apps* sharing native services and a store (FinClip,
WeChat, and kin)" (`SNAP\base\doc\design\STZSUPERAPP_DESIGN.md` §0; first committed 2026-07-09 per git).
And for the engine, Softanza's own past is the field's normal case: a scripting library resting on a large
C++ framework, Qt, for its Unicode, dates and files (`stz-vs-qt-unicode-narration.md`, marked "HISTORICAL
NOTE"; `SOFTANZA_ENGINE_MACROPLAN.md` Phase 2 table, "Replaces: QString2, QChar, QDate/QTime/QDateTime,
QFile/QDir/QFileInfo, QLocale, QRegularExpression, QJsonDocument").

Both pictures put the court outside: a test suite beside the code, a review beside the store. Neither draws
the judge as a column standing at every floor. That is what Chapter 4's figure adds.


### Block 7 — the platform refuses to deploy what it has not built (KEPT)

## 5. The decision, and what was refused

From the record's rulings, design documents and memos. Speaker marked for each.

1. **The engine is the product; the language adds beauty, not computation.** "Ring adds beauty, not
   computation. 6000+ semantic methods, natural coding, Q() chaining -- but zero algorithms."
   (`SOFTANZA_ENGINE_ARCHITECTURE.md` §12, principle 4; a design document in the library, 2026-05-15 per git;
   author not stated in the file.) Refused: computation in the faces.
2. **Qt was purged, with no fallback.** "ALL Qt code paths removed from Core and Base … Engine-only: no
   fallback, no feature flags, no Qt dependency" (`SOFTANZA_ENGINE_MACROPLAN.md`, Phase 3, Session 2; a
   session's record). Refused: a dual path kept "just in case".
3. **The language Softanza was born on was retired; its surface kept.** The author's ruling, in the author's
   words as the study reports them: "The future is Haro, not Ring" (study 12.10, ruled 2026-10-07 11:10 UTC).
   The vision corpus: "What is not carried is **Ring's runtime and Ring's governance**" (`vision/01-KERNEL.md`,
   amendment 2026-09-12, session text ratified by the author). The loss published with it: "Luau leads all
   six rows, 1.04 to 1.88 times" (study 12.10). Chapter 1 already tells this; chapter 4 only places it on the
   picture (the faces above the engine).
4. **Sovereignty means a verdict per dependency, not "every line ours".** "The estate's word has one
   meaning: **nothing anyone else can withdraw.** It never meant 'every line ours'." (`vision/07-SYSTEM.md`,
   "Sovereignty at the floor", ratified chapter). This is the record's own answer to the 19 vendored libraries.
   Refused: borrowing that cannot be pinned (the Wi-Fi blob: "none … not taken", same table).
5. **Three layers, one dependency rule, and a layer chosen by the file you load.** The author's ask (study
   12.15, the question, paraphrased by the study): CORE for small devices and lean binaries, BASE for the
   majority, MAX for the strong innovations. What was refused, in code: a runtime flag. "a flag that silently
   does nothing is the part that misleads" (`SNAP\stzLib.ring` header; a session's comment). And the debt, in
   the author's sentence as the study gives it: "under the pressure of time, everything went into BASE"
   (12.15). Chapter 1 already confesses it; chapter 4 draws it (base widest, inheritance arrow broken).
6. **Worlds, not mini-apps.** "Softanza refuses it and asks what a super-app **is**" — the host + runtime +
   mini-apps model (`STZSUPERAPP_DESIGN.md` §0; a forward design piece). "The load-bearing shift: **worlds,
   not mini-apps; a governed graph, not a host container.**" (same, §1).
7. **Model the solution before the features; deploy a platform, never a profile.** "*We do not deploy a
   profile — we deploy a platform and its parts.*" (`SOFTANZA_SYSTEM_FOUNDATION.md` §2.2). Refused: code
   written against an ambient "current" system ("never write feature code against 'current'", §2.1).
8. **Courts read contracts, never runtimes; one escape door.** "Courts consume contracts, never runtimes."
   (`REFERENCE_DESIGN.md` §2, doctrine 4, ratified 2026-08-08). "No further host embeddings; the door is the
   answer to 'what about language X'." (`vision/02-STACK.md`, "The escape door").
9. **The architect is a role the picture needs.** Study 12.13 (ruled 2026-10-07 19:37 UTC): the architect is
   "the ninth journey, the one that spans the vertical". A reader's ruling, from the author's question.

What the record does **not** hold as a decision: why the courts are a column rather than a floor (the
picture's own design); whether `stx*` will be loaded or the contract amended (12.15 B20 is open: "One
decision, the author's").

  and every floor you write to has a court that will read you (Blocks 6, 7).
